# 既存の将棋 GUI の流れと、このソフトの問題点（2026-09-09）

Windows で実機確認できたあと、既存のソフト（ShogiHome・将棋所・ShogiGUI）を人がどう使うかを Web で調べ、
このソフトの問題点を洗った。直したものと、残した提案を分けて書く。

## 調べたもの

- ShogiHome: [wiki「エンジンを使う機能の操作方法」](https://github.com/sunfish-shogi/shogihome/wiki/エンジンを使う機能の操作方法)、
  [wiki「基本的な操作方法」](https://github.com/sunfish-shogi/shogihome/wiki/基本的な操作方法)、
  ソースの `EngineAnalytics.vue` / `EngineAnalyticsElement.vue` / `EvaluationChart.vue`、
  [アプリ設定の記事](https://note.com/ryosuke_kubo/n/n2d312d10f908)、[勝率換算グラフの記事](https://note.com/ryosuke_kubo/n/n2c1cf65f6e4e)、
  [検討の手順の記事](https://imonote.hatenablog.jp/entry/2024/10/06/153336)
- 将棋所: [使い方](https://shogidokoro2.stars.ne.jp/usage.html)
- ShogiGUI: [評価値グラフ](http://shogigui.siganus.com/manuals/graph.html)、[使い方の記事](https://hibitonshi.com/2021-12-18-133500_3/)

## 人がソフトを使う流れ（3 本に共通）

1. **対局**。対局設定で人かエンジンかと時間を決める。対局中は手番のエンジンの思考（予想手・深さ・NPS・評価値・読み筋）が
   画面の下に出て、評価値グラフが対局者の評価で伸びていく（将棋所「思考情報」、ShogiHome は対局者のエンジンを検討と同じ欄に出す）
2. **終局**。結果が出て棋譜が残る（将棋所は自動保存）。そのまま **棋譜解析** に進む。全手を順に評価してグラフを埋め、悪手に印を付ける
3. **検討**。グラフや棋譜を押して気になる局面へ移り、検討（MultiPV・読み筋・盤の矢印）。読み筋を継ぎ盤で再現し、分岐を棋譜に挿入する
4. 検討は局面を動かしても追従し、「停止／再開／検討終了」で制御する（ShogiHome）。将棋所は Space で開始・停止、Esc で終了

## ShogiHome の UI から取ったこと

- **思考と検討は同じ場所**。`EngineAnalytics` は対局者のエンジンと検討のエンジンを縦に並べる 1 つの欄。見出しにエンジン名・予想手・最善手・NPS・ハッシュ使用率、
  表の列は 時間 / 順位 / 深さ / ノード / 評価 / 読み筋。「思考」タブは履歴、「読み筋」タブは最新だけ
- **評価値グラフ**は対局者（先手・後手）と検討の系列を色で分ける。赤い縦線が現局面。押すとその手数へ移る。評価値（±2000）と期待勝率（0〜100%）の 2 種
- 矢印は上位 3 手（設定で 0〜）。評価値の符号は「先手有利がプラス」に統一できる
- タッチ向けに大きなボタン、盤のレイアウトが選べる、カスタムレイアウト

## 残した提案（優先順）

1. **読み筋の再現（継ぎ盤）と棋譜への分岐の挿入**。ShogiHome の「▶ 再現」「棋譜に挿入」。検討の中心の操作で、これが無いと読み筋は文字で追うしかない
2. **棋譜解析の結果を棋譜に残す**。評価値の列、悪手・疑問手の印（ShogiGUI の ▲▼）、KIF のコメントに読み筋
3. **対局中の検討の扱い**。ShogiHome も将棋所も対局中は検討を開かない。いまは棋譜解析だけ確認を出す。検討の開始も対局中は確認するか、対局の枠だけにする
4. **検討の「停止／再開」**。エンジンを立てたまま休ませる（起動が重いエンジン向け）。いまは止めると次に起動し直す
5. **ショートカット**。Space で検討の開始／停止、Esc で終了（将棋所）。矢印キーは済み
6. **終局のダイアログと自動保存**。将棋所は対局後に自動保存し「対局結果一覧」から開ける
7. **棋譜コメント・しおり**、局面図の書き出し
8. 見出しの予想手（ponder）・ハッシュ使用率。ハッシュが 90% を超えたら赤（ShogiHome）
9. ~~評価値の目盛り（±2000）表示は入れない判断~~ → **2026-09-09 に撤回**。下の「第 2 回」を見る


# 第 2 回（2026-09-09）: 評価値の併記と、ShogiHome の割りつけ

指摘は 4 つ。「出しているのは期待値ではなく勝率ではないか」「両方出したい」「UI をなるべく ShogiHome と同じに」「今の UI は使いにくい」。

## 1. 出していたのは勝率だけだった

そのとおりで、グラフも候補表も**先手の勝率**しか主役にしていなかった（候補表の隅に cp を小さく添えてはいた）。
ShogiHome の呼び方に合わせ、以後この 2 つを次の名前で**両方**出す。

| 名前 | 中身 | ShogiHome の語 |
|---|---|---|
| 評価値 | エンジンが出す cp。先手から見た符号 | `評価値`（`rawScore` / `score`） |
| 期待勝率 | 先手が勝つ確率 0〜100% | `期待勝率`（`estimatedWinRate`） |

- **グラフはタブで 2 種**。ShogiHome の `EvaluationChartType.RAW`（±2000）と `WIN_RATE`（0〜100）と同じ分け方。
  縦軸は評価値なら +2000 / +1000 / 0 / −1000 / −2000、期待勝率なら 100 / 50 / 0%
- **カーソルの脇は両方**出す（「先手 28.1% · ≈−442」）。開いているタブの量を先に置く
- **候補表は列で並べる**。ShogiHome の 順位 / 深さ / Node数 / 評価値 / 読み筋 に**期待勝率**を足した 6 列

### 撤回した判断（第 1 回の残した提案 9）

「エンジンごとに目盛りが違うから、共通の通貨は勝率だけにする」は撤回する。理由と、代わりに置いた歯止め:

- 1 本の cp 軸に載るのは **別々の目盛りの数字**である。エンジン A の cp（FV_SCALE 16）、エンジン B の cp（同 24）、
  そして 1〜40 手目は**勝率から換算した cp**（布石の価値ネットは cp を持たない）
- ShogiHome も dlshogi 系で同じことをしていて、そのまま出している。出すこと自体は筋が通る
- ただし**黙って混ぜない**。換算した点は「中を抜いた丸」で描き、凡例に「○ 勝率からの換算」を出す。
  数字にも `≈` を付ける（`≈+106`）。内蔵の布石評価は `info` に `score cp` を**出さない**ようにし、
  換算は受け手（`evalOfInfo`）が 1 か所でやる。どこで作られた cp か型で分かる（`EvalPoint.approx`）
- 布石中の **深さ・Node数 は出さない**（`—`）。価値ネットの内部の数字で、読みの深さではない

## 2. 割りつけを ShogiHome の標準レイアウトに

`StandardLayout.vue` は splitpanes で **上（盤 ＋ 棋譜）／下（タブの欄）**に割り、比率を持つ。
こちらは右の 380px の列に「名札・棋譜・検討」を縦に 3 つ積んでいて、検討が下 1/3 に押し込まれ、
候補が 1 行しか見えなかった。**これが「使いにくい」の中身**である。

- 上は 盤 ＋ 棋譜、下は**幅いっぱいのタブの欄**（検討 / 評価値 / 期待勝率）に変えた
- 仕切りは 2 本とも掴んで動かせる（キーボードは矢印。Shift で 4 倍）。位置と開いていたタブは設定に残す
- 下の欄は窓の高さの 4 割まで。狭い窓で盤が潰れない
- 検討の枠は幅に応じて**横に並ぶ**（1 枠 380px を下限に auto-fit）。対局の枠は席の 2 つが左右に並ぶ
- 見出しは 1 行（「検討を始める」「候補」「＋ エンジンを足す」「棋譜解析」）。380px の列でなくなり折り返さない

## 3. まだ ShogiHome に無いもの・入れなかったもの

- **継ぎ盤（読み筋の再現）と棋譜への分岐挿入**。第 1 回の提案 1 のまま。検討の中心の操作で、次に入れるならここ
- **予想手（ponder）**。`info` ではなく `bestmove … ponder …` から取る。ハッシュ使用率は入れた（`Hash 41.2%`）
- **コメント・しおり・棋譜情報のタブ**。棋譜側の機能がまだ無いので、タブも作っていない
- **タブの分割（DOUBLE / TRIPLE）**。1 つの欄にタブを並べる形（SINGLE）だけにした


# 第 3 回（2026-09-09）: 割りつけを利用者に渡す

指摘は 2 つ。「利用者が自由にレイアウトを変更できるようにしたい」「候補手とグラフが同時に見れない」。

第 2 回でタブにしたのが原因である。ShogiHome の `TabPaneType` は SINGLE / DOUBLE / TRIPLE を持ち、
DOUBLE 以上では**下の欄が左右に割れて、検討とグラフが同時に出る**。こちらは SINGLE だけを作っていた。

## 直したもの

- 下の欄を「欄」の並びにした。欄はタブを何枚か持ち、そのうち 1 枚を開く。
  **既定は 2 欄**（左に検討、右に評価値と期待勝率）。これで候補手とグラフが同時に見える
- 組み替え方は 3 つ。どれか 1 つが効かない環境でも困らないようにしてある
  1. タブを**掴んで**別の欄へ落とす（WebKitGTK で `draggable` は効くことを実機で確認）
  2. **欄の境**を掴んで幅を変える（キーボードは矢印。Shift で 4 倍）
  3. **「配置」の窓**。ひな形（1 欄 / 2 欄 / 3 欄）と、タブを左右の欄へ送る ← →、初期に戻す
- グラフは 2 つ立てる（評価値・期待勝率）。別々の欄に置いて同時に見られる
- 下の欄の高さの上限を「窓の 4 割」から「盤に 300px 残す」へ。
  4 割の頭打ちは、狭い窓で盤が潰れるのを防ぐためのものだったが、
  **候補をもっと出したくて広げる利用者の手を黙って止めていた**。窓の側の都合を利用者の意図より前に置かない
- 凡例をグラフの枠の上の余白へ。欄が狭いと「本将棋」の見出しと重なっていた

## 覚えておくこと

- 設定は古い形（タブ 1 枚を覚えるだけの `tab`）から引き継ぐ。実機の `settings.json` はその形で残っていた。
  煙テストは localStorage に古い形を書いてから読み直して確かめる
- **欄が狭いと検討の枠は 1 列に落ちる**（`minmax(480px, 1fr)`）。エンジンを 3 本並べるときは
  「配置」で 1 欄にすると 2 列になる。これは不具合ではなく、欄ごとに決められることの効き目である
- 閉じたタブの要素は幅 0。グラフは開いている欄の分だけ描く（`Layout.visible`）


# 第 4 回（2026-09-09）: 使い勝手 11 件

画面の写真つきで 11 件。直したものと、その理由。

| # | 指摘 | 直したこと |
|---|---|---|
| 1 | ドラッグ＆ドロップで割りつけを変えたい | **作り直した**。`button` に `draggable` を付けても掴めない WebView があるので（button は押下を自分で処理する）、仕切りと同じ pointer の作りに。落とし先は欄・欄の境・下の欄の左右の端。境と端は新しい欄になる。実機（WebKitGTK）で運べることを確認 |
| 2 | 人が後手なら盤を自動で反転 | 人が 1 人だけの対局は、その人の側から向ける。「盤面反転」を押したら以後は自動で動かさない（次の対局で解ける） |
| 3 | デザイン改善 | 道具の並びが 2 行に折れていたのを 1 行に（狭い窓では右から字を落として絵だけに）。候補の数の入力が潰れていたのを直した。布石の候補表から「深さ」「Node数」の列を外し、読み筋に幅を回した |
| 4 | 対局を一時停止したい | 「一時停止」。考えているエンジンを止め、時計を止め、盤も触れなくする。止めた瞬間の読みは捨てる（`gen` を進めるので遅れて届く `bestmove` は指されない） |
| 5 | 持っていない駒は出さない（薄いのもいらない） | 駒台は持っている駒だけ。局面編集だけは全種類を並べる（無い駒を盤へ置く台なので）。駒が減っても台の形は変わらないよう 4 段ぶんの高さは残す |
| 6 | 暗いときに反転していて分かりづらい | 盤と駒台を落とした（#96662a / #7d5522）。**明るい盤のままだと画面でいちばん眩しいのが盤**になり、地と図が入れ替わる。駒は面を `#fff7b7` で塗ってあるので、盤を落としても字と成駒の朱は落ちない（`public/pieces/*.svg` を見て確かめた）。盤の上に置く色（陣・直前の手・選択・王手）も明るい側へ振った |
| 7 | スクロール必須で使いづらい | 候補手を別のタブに分けた（下記 8）。表に出す候補は「候補」の数まで（内蔵の布石評価は 16 手ぶん返していた）。枠ごとに表がスクロールし、見出しは動かない。二重定義になっていた CSS も直した |
| 8 | 検討と候補手でタブを分ける | 「候補手」タブを新設。既定の並びは 左に 候補手＋検討、右に 評価値＋期待勝率 |
| 9 | 片方が人でも先後で半分に分ける | 候補手の欄は対局のあいだ**常に左右 2 つ**（左が先手、右が後手）。人の側は「人が指します」。`grid-template-columns: 1fr 1fr` の固定で、欄が狭くても縦に積まない（検討の枠の auto-fit とは別の規則） |
| 10 | エンジン同士なら盤に矢印を | 出す。人が入っている対局では出さない（手を先に見せない）。内蔵の評価は読みが一瞬で終わるので、矢印を描く間を 1 フレーム取る |
| 11 | （写真）候補の数の入力の潰れ | 3 と同じ |

## 覚えておくこと

- **設定の形を変えたら移行を書く**。`layout.tab`（1 枚）→ `layout.panes`（欄の並び）→ 候補手タブの追加、と 2 回続けて変えた。
  増えたタブは「相方の居る欄」へ入れる（候補手は検討の隣、評価値は期待勝率の隣）
- 実機の WebKit のインスペクタには `Input` ドメインが無い。実機で掴む操作を試すには `PointerEvent` を作って流す
- `setPointerCapture` は捕まえられないことがある。move / up は `window` で受けて、capture は付けられたら付ける程度に使う


# 第 5 回（2026-09-09）: 3 件

| 指摘 | 直したこと |
|---|---|
| 布石のときは駒を持っているので薄くしない（このアプリで薄くする場面はない） | 駒台から `.dim` を消した。布石のあいだは 20 枚を持っているのでそのまま並べ、置けない駒は**押せなくするだけ**。局面編集では持っていない駒も普通の濃さで並べ、枚数（0 枚を含む）を数で示す |
| 候補手が 1 つしか出ない | 対局中のエンジンに **MultiPV を送っていなかった**（既定は 1）。候補手の欄の「候補」で数を決めて送る（既定 3）。水匠5 の実機で 3 行出ることを確認 |
| ふつうの将棋も指せるように | 「新しい対局」に**本将棋**を足した（平手の初期局面から `mode: 'position'`）。布石のエンジンと強さの欄は隠れる |

あわせて、狭い欄で読み筋が潰れないように **Node数 の列を落とした**（行ごとに同じ数で、見出しの行にも出ている）。
見出しの数は 万・億 で短くする（`921.3万 ノード · 460.2万 NPS`）。
